# Laboratory 09 – Mission Reflection

Throughout this laboratory, I learned that automation is an important part of managing cloud infrastructure. When an organization manages hundreds of cloud servers, performing tasks manually can take a lot of time and may cause human errors. Automation allows administrators to run repetitive tasks, such as backups, updates, and system checks, more consistently. It also gives IT teams more time to focus on other important responsibilities.

However, automation also has potential dangers. A small mistake in a script can cause serious problems, especially when the script runs on hundreds or thousands of servers. For example, a destructive command or incorrect folder path could accidentally delete important files. If the script is scheduled to run automatically, the damage could happen before an administrator notices it. Because of this, scripts should be reviewed, tested in a safe environment, and monitored before they are used in production.

Writing a Bash script was different from creating a Docker Compose YAML file during Mission 6. In Bash, I wrote commands that execute one after another to perform a task. In Docker Compose, I used YAML to describe services, configurations, ports, and environment variables. Both tools help automate work, but Bash focuses on executing commands while Docker Compose focuses on defining and managing application services.

Reviewing my GitHub portfolio from Laboratory 1 to Laboratory 9 helped me understand how cloud computing connects different technical skills. I started by learning basic Linux commands and system information. Later, I explored cloud infrastructure, storage, containers, deployment, and operations. In this laboratory, I applied my knowledge by creating an automated backup and scheduling it with cron. These activities helped me see how different cloud technologies work together.

The role I enjoyed most was the Cloud-Native Engineer because I found working with Docker and deploying applications interesting. I also appreciated learning automation because it makes technical tasks faster and more organized. Overall, this semester helped me become more confident using Linux commands, troubleshooting errors, and documenting my work. I realized that becoming a cloud engineer requires continuous learning, careful testing, and responsibility when managing systems and data.
